# Translations

The app ships in English and Italian. Every user-facing string lives in
`src/i18n/en.json` and `src/i18n/it.json`; components read them through the
`useI18n()` hook.

## Using strings

```tsx
import { useI18n } from "~/i18n/LocaleProvider";

function SaveButton() {
  const { t } = useI18n();
  return <button>{t("common.save")}</button>;
}
```

- Keys are flat and dotted: `area.screen.element` (`tree.settings.invite`).
- Reuse `common.*` when the wording is identical. Do not reuse a key when the
  Italian translation would need different wording for the same English text.
- Interpolation uses `{name}`: `t("tree.memberCount", { count: 3 })`.
- A numeric `count` automatically selects plural keys. Define `.one` and
  `.other` (add `.many` only if Italian needs it):

```json
"common.person.one": "{count} person",
"common.person.other": "{count} people"
```

```tsx
t("common.person", { count: 3 });
```

- A sentence with inline markup uses `Trans` and named component tokens:

```json
"auth.login.newHere": "New here? {createAccount}"
```

```tsx
<Trans
  key="auth.login.newHere"
  components={{ createAccount: <A href="/register">{t("auth.register.title")}</A> }}
/>
```

- Prefer splitting a sentence into separate keys over `Trans` when the parts
  stand on their own.
- Never build a sentence by concatenating translated fragments; word order
  differs between languages.

## Locale

- `useI18n()` also exposes `locale()` and `setLocale("it")`.
- The locale comes from the `family_tree_locale` cookie, then the browser
  language, then English. The cookie is written when someone switches.
- `LocaleSwitcher` (`~/i18n/LocaleSwitcher`) is the shared control. Use
  `variant="text"` on public pages and the icon variant inside app headers.
- Date and number formatting takes the locale:
  `formatDate(value, locale())`, `formatRelative(value, locale())`,
  `formatFuzzyDate(date, { locale: locale() })`,
  `formatFuzzyYears(birth, death, locale())`.
- Text generated outside components (upload helpers, action results) uses
  `tClient()` so it follows the client locale.

## Adding a language

1. Copy `en.json` to `<code>.json` and translate every value.
2. Add the code to `LOCALES` and the dictionary map in `src/i18n/index.ts`.
3. Add the native name to `LOCALE_NAMES` in `src/i18n/LocaleSwitcher.tsx`.
4. Run `pnpm typecheck` and `pnpm test`; both enforce key parity.

## Never translate

- Brand names (`family-tree`), person and tree names, biographies, and other
  user data.
- Transactional emails (English only for now), GEDCOM/ICS output, API payloads,
  logs, Sentry data, and analytics event names.
- Legal pages and developer API documentation: both stay English by design,
  with a translated note on the legal pages.
